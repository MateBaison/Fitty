# Account activity and temporary reset

`public.account_activity` stores one server timestamp per authenticated account. `record_app_activity()` accepts no identity or timestamp parameters; it derives the caller from `auth.uid()`. Only authenticated users may execute it, and neither anonymous nor authenticated API clients may read/write the table directly. The function coalesces writes within five minutes. The dashboard SQL report in `scripts/reports/account-activity.sql` joins email addresses privately as administrator, without exposing a view of auth.users.

The browser records entry into an authenticated app screen, return to a visible tab and trusted pointer, keyboard or scroll interaction. There is no idle heartbeat. Requests are throttled to five minutes on success and one minute after failure, and cancelled on account disposal. No page contents, event payloads, location or input values are recorded. This is an approximate last-use signal, not evidence of a completed workout; old activity and use of the archived HTML site cannot be inferred.

The temporary ResetAccount control in Profile uses the existing account change/flush path. It requires typed confirmation and successful sync first, saves a local account-scoped JSON backup and offers the same backup as a download before replacing the snapshot with clean defaults. It retains authentication and only navigates to onboarding after cloud confirmation. Failed sync remains retryable. Restore with Profile → Import backup after onboarding. This does not delete the authentication account or activity row. Remove ResetAccount and its AccountPanel entry when testing ends.
